# tg-agent

Юзербот-аккаунт ТГ (слот tg-hr, +79955656840) + CLI для HR-переписки. Управляется Claude Code через скилл **tg-hr** (`~/.claude/skills/tg-hr/SKILL.md`).

## Установка

```bash
py -m pip install telethon
cp phone.env.example phone.env   # TG_PHONE=+7...
py login_interactive.py          # код из ТГ (+ пароль 2FA, если есть)
```

## CLI

```bash
py tg.py me                  # сессия жива?
py tg.py unread              # личные чаты с непрочитанными
py tg.py dialogs [-a]        # последние чаты
py tg.py read "Александра" -n 10
py tg.py send "Александра" "текст"
py tg.py send "Максим Сергеевич | ЕГЭ, ОГЭ" --format html "<b>Заголовок</b>\n\nТекст"
py tg.py edit "Максим Сергеевич | ЕГЭ, ОГЭ" --msg 123 --format html --text-file .outbox/post.html
py tg.py send "@HRiMediaSolutions" "текст"  # новый контакт: @юзернейм или t.me-ссылка
py tg.py sendfile "Александра" resume.pdf caption  # отправить файл (резюме и т.п.)
py tg.py send me "себе в избранное"
py tg.py mark "Александра"   # отметить прочитанным
```

`<chat>` в send/sendfile: подстрока имени, числовой id, а если чата ещё нет —
`@юзернейм` или t.me-ссылка (resolve_chat найдёт контакт и создаст диалог).
Правила для агента («людям пишем только через humanizer-framework», отправка
через `tg.py`) — в **AGENTS.md**.

Для постов Telegram поддерживается `--format html`. Разрешены стандартные теги
`<b>`, `<i>`, `<u>`, `<s>`, `<code>` и `<a href="...">`. Команда `edit` меняет
только собственные сообщения и посты.

## Сканер вакансий

`py scan_jobs.py scan` — дефолты берутся из ПРОФИЛЯ поиска в `config.json`
(`active_profile` + `profiles`; CLI-флаги сильнее профиля). Профиль = дни, мин. ЗП,
лимит, `remote_only` и список каналов (`@хэндлы` или числовые id для приватных без
username). Результаты копятся в `vacancies/vacancies.jsonl` + дневной `vacancies/digest-*.md`.
Шум отсекается сам: посты-«резюме» кандидатов, обзоры рынка; `remote_only: true` —
офисные/городские посты без упоминания удалёнки.

`py scan_jobs.py push [-n 20]` (или `scan --push`) — разослать находки карточками
себе в Избранное (канал, дата, ЗП/стек, ссылка, текст) — доставка в духе CorgiWork.
Дедуп по `vacancies/pushed.json`: можно гнать по расписанию, повторов не будет;
неотправленное остаётся непомеченным и уйдёт в следующий прогон.

## Лиды и рассылка

> **Установка Макса (01.10.2026): цель любыми способами попасть на собес.** Формулировки
> в текстах эйчарам — максимально выгодные, без скромности; навыки — уверенно («трогал
> всё из стека»). **Срезающие конверсию ответы запрещены** (за «релокейт не планирую»
> отдельно ругался): дефолт всегда «готов / рассматриваю / да» — релокейт, переезд,
> форматы, тестовые. Проверяемые документально факты (стаж в роли под выписку из
> трудовой) не выдумывать — иначе мгновенный отказ на проверке.

Из постов каналов вытаскиваются контакты (@юзернеймы, email, t.me-ссылки), инвайт-ссылки
(t.me/+hash, joinchat) и прочие URL (карьерные страницы/АТС) — в одну базу
`leads/leads.jsonl` с дедупом, источником (канал, пост, ссылка) и сниппетом-контекстом.
Юзернеймы/email/ссылки/инвайты разбираются врозь (`show --type`). Telegram-outreach
пока берёт только username; email сохраняются для отдельного будущего конвейера.
Правило «уже писали — не пишем»: outreach берёт только статус `new` и после
успешной отправки ставит `contacted`, так что повторный прогон дубликатов не создаёт.

```bash
py leads.py scan [--limit 500] [--profile react | --channels @a @b]   # глубокий скан контактов
py scan_jobs.py scan --profile ml                                  # собрать ML-вакансии без рассылки
py leads.py prescribe --profile react --limit 500 --daily-new-limit 20 # фильтры + до 20 новых TG HR/сутки
py leads.py reconcile                                                  # ответы в ЛС: contacted → replied
py leads.py show [--type username|email|invite|url] [--status new] [-n 50]  # что нашлось
py leads.py set @user contacted "ответил"                             # статус вручную
py leads.py post @user                       # полный текст вакансии-источника лида
py humanize.py [-n 5] [--leads @a @b]        # карта персональных текстов (humanizer-framework)
py humanize.py @user                         # один текст в stdout, быстро посмотреть
py leads.py outreach --map texts.json --resume resume.pdf             # свой текст каждому (сначала --dry-run)
```

`humanize.py` — тот же humanizer-framework, что в profi-worker (домен job_search,
канал telegram): генерит текст под конкретную вакансию голосом Макса, прогоняет
через свои валидаторы + LLM-грейдер. Сам ничего не отправляет — пишет карту
`outreach-humanize.json`, отправка — `outreach --map` после просмотра. LLM — как
в profi-worker: по умолчанию anthropic-протокол z.ai (`ANTHROPIC_AUTH_TOKEN` →
`api.z.ai/api/anthropic`, glm-5.3-flash, thinking выключен), ключи/токен из env
или `llm.env`, при лимите перебор цепочки. Запасные: `--provider glm`
(OpenAI-протокол, другой пул квот) и `--provider claude` (локальный claude CLI).

`py scan_jobs.py scan` тоже попутно собирает лиды из каждого прочитанного поста.

## Реестр источников

`py sources.py harvest` — обойти вакансионные подписки и обновить `sources.json`
(username, about, участники, сайты из описаний; ручные поля tags/priority/status/notes
не трогает). `py sources.py sites --from-vacancies --save` — вытащить уникальные
сайты (описания каналов + тексты вакансий, группировка по доменам, без utm) в
`sources-sites.md` — сырьё для браузер-агента (прямые карьерные страницы/АТС компаний).
Человеческая документация — job_channels.md. Подробнее — в докстрингах.

## Автоответчик HR

Для генерации текущей моделью Codex без отдельного LLM-провайдера доступен
`humanize_local.py`: `prepare --request .outbox/request.json --out .outbox/package.json`
готовит инструкции настоящего фреймворка. Агент пишет кандидат по этим инструкциям,
затем `validate --package .outbox/package.json --text-file .outbox/draft.txt --out .outbox/validated.txt`
нормализует и проверяет его. Запрос JSON использует поля `CommunicationRequest`
(channel, domain, message_type, conversation, context, business_rules, voice,
constraints). Профиль и факты задаёт вызывающий проект. При hard-ошибках команда
возвращает код 2 и не оставляет выходной текст. Отдельный LLM-грейдер не запускается.
После успешной проверки отправляется точное содержимое validated.txt через tg.py.

## TG Ops Control Center

Полноценная локальная админка для статистики, Telegram-переписок, HR-базы,
управления процессами, логов и AI Manager:

```bash
python admin.py
```

Открой http://127.0.0.1:8765. Основные разделы:

- **Обзор** — HR в базе, новые лиды, допуск в очередь, фактические первые касания,
  входящие/исходящие, резюме, сканы, активные чаты и статистика аккаунтов.
- **Переписки** — список личных диалогов, история, кликабельные Telegram-профили
  и подготовка Reply через humanizer-framework. Сгенерированный текст нельзя
  незаметно отредактировать; отправка — отдельное действие.
- **HR-база** — контакты, статусы, источник вакансии и быстрые ссылки на Telegram
  и исходный пост. Статус лида можно изменить из интерфейса.
- **Процессы** — запуск/остановка разрешённых worker-команд, состояние PID и логи.
  Автопилот, который может отправлять сообщения, запускается с дополнительным
  подтверждением.
- **AI Manager** — чат-агент, использующий существующий провайдер из конфигурации
  Humanizer. Он может искать HR, читать диалоги, анализировать данные, готовить
  сообщения, отправлять одно сообщение по явной команде и запускать безопасные
  операции из allow-list.
- **Логи** — вывод процессов, автопилота и журнал телеметрии.

### LangiaFlow Content Studio

Отдельная страница `/content` использует темы и карточки из приватного
Personal Wiki (`Generated Content/LangiaFlow`), а тексты готовит через
Humanizer Framework в режиме `channel_post`. Одна тема — один черновик —
одна ручная публикация. Источники архива помечены `reviewed: false`, поэтому
проверка источника и текста обязательна. Повторные темы сверяются с историей
канала; отправка идёт через общий sender в `tg.py`.

Настройка GitHub read-only token, отдельной Telegram-сессии, прав канала и
systemd unit описана в [docs/CONTENT_STUDIO.md](docs/CONTENT_STUDIO.md).
Для сервера устанавливается отдельный `tg-ops-control-center.service` на
`127.0.0.1:8765`; существующий HH Ops admin на порту 8001 не заменяется.

### Безопасность и ограничения

- Админка слушает только localhost. Для удалённого доступа используй SSH tunnel;
  не выставляй порт напрямую в интернет.
- AI Manager не получает shell-доступа и не может выполнить произвольную команду.
- Все сообщения HR создаются через humanizer-framework. Первое холодное касание
  дополнительно проверяет статус лида, свежесть поста и отсутствие существующего
  Telegram-треда. Резюме автоматически не прикладывается.
- Ручные переписки и контакты из пользовательских Telegram-папок остаются
  защищёнными. Если админка не может проверить папки Telegram, отправка блокируется.
- Если последнее сообщение в диалоге наше, повторное касание блокируется.
- Процессы, запущенные внешним Task Scheduler/cron, можно увидеть по lock-файлам
  и логам, но кнопка Stop управляет только процессами, запущенными самой админкой.
- Одновременно не запускай несколько `cron-run.py`: дневное состояние и
  блокировка автопилота общие для проекта. Responder также должен работать
  только в одном экземпляре, поскольку его inbox/state общие.

### Несколько Telegram-сессий

Скопируй пример и укажи свои локальные файлы сессий:

```bash
cp sessions.example.json sessions.json
```

Пути `session` задаются относительно корня репозитория или абсолютными путями;
расширение `.session` указывать необязательно. Если `sessions.json` отсутствует,
админка ищет `*.session` в корне проекта и в `sessions/`.

Операции и AI Manager используют выбранную сессию. Автопилот остаётся единой
операцией с общим дневным лимитом и состоянием; это не распределитель нагрузки
между аккаунтами.

### Телеметрия и точность

События хранятся в локальном `ops-data/events.jsonl`, история чата AI Manager —
в `ops-data/agent-chats/`, логи управляемых процессов — в `ops-data/logs/`.
Эти данные не коммитятся. Содержимое HR-переписок не добавляется в telemetry
events, но история диалога AI Manager может содержать текст запросов и ответов.

Счётчики фактических отправок и сканов начинают накапливаться после установки
телеметрии. Исторические данные берутся из `leads/leads.jsonl`, если там есть
соответствующие даты. «Новые HR» — дата добавления в базу; «допущено в очередь» —
дата допуска; «первые касания» — фактический `contacted_at`. Эти показатели
не смешиваются.

## Статистика humanizer

Генерации автоматически пишутся самим humanizer-framework в его общий
telemetry JSONL без содержимого промптов и сообщений. Сводка по генерациям,
лидам, сценариям, моделям, ошибкам, времени и токенам:

```bash
py humanizer_stats.py
```

`py responder.py` — демон: следит за личкой (новые входящие → `inbox.jsonl` + тост,
та же роль, что у `watcher.py` — **watcher при живом респондере не запускать**),
отвечает эйчарам по базе знаний `answers.json` ТОЛЬКО по заложенным фактам;
чего нет в базе — эскалация: тост + сообщение в TG-бота, ответ Макса Reply-ем
уходит эйчару. Автоответы только для чатов из `hr-auto.json` (`auto_chats`);
задержка 2–8 минут, всегда в пределах 10; персональное (always_escalate) автой
не уходит никогда; перед отправкой перепроверка «эйчар дописал?». Сессия —
короткими циклами, `tg.py` влезает между ними. Креды бота — `hr.env`
(`cp hr.env.example hr.env`, токен от BotFather; `/start` боту запомнит chat_id).

```bash
py responder.py          # демон
py responder.py --once   # один цикл, проверка
```

## Хуки

Pre-commit форматирует staged `.py` (ruff format + ruff check --fix) перед каждым
коммитом и блокирует коммит при неисправимых ошибках линтера. Активация один раз
на клон: `git config core.hooksPath githooks`. Тот же набор правил гоняет CI
(ruff lint + format + синтаксис-проверка).
